# 실제 게스트 모드 구현 플랜

> **상위 마일스톤**: 루트 `todo.md`의「게스트 모드 & Import API」절에서 완료 여부를 관리한다.
> **상태 기준일**: 2026-08-20

**목표:** 이메일 로그인 없이 로컬 보드를 실제로 생성·편집하고, 로그인하면 해당 데이터를 안전하게 계정으로 가져올 수 있게 한다.

**현재 상태:** M1의 진입 라우팅과 게스트 플래그만 구현되어 있다. 실기기 Profile 빌드에서 `게스트로 시작` 진입과 앱 실행은 확인했지만, `GuestHomeScreen`은 이메일 로그인 버튼만 있는 플레이스홀더이므로 현재는 실제 게스트 체험이 불가능하다.

**전체 완료 기준:**

- `게스트로 시작`을 누르면 플레이스홀더가 아니라 기존 보드 목록·상세 UI로 진입한다.
- 보드·컬럼·카드 생성/수정/이동/삭제 결과가 앱 재실행 후에도 유지된다.
- 게스트 구간에서는 HTTP, WebSocket, FCM 토큰 등록을 호출하지 않는다.
- 참가·초대·담당자·멘션 등 협업 기능은 로그인 필요 안내를 표시한다.
- 로그인 후 Import가 실패하면 로컬 데이터를 유지하고, 성공이 확인된 데이터만 삭제한다.
- iOS 실기기 Profile 및 지정 시뮬레이터에서 핵심 시나리오를 통과한다.

## 0. 고정 정책과 최소 설계

| 항목 | 결정 |
|------|------|
| 로컬 저장소 | 이미 사용 중인 `GetStorage`에 버전이 있는 JSON(`guest_boards_v1`)으로 저장한다. 별도 DB 패키지는 추가하지 않는다. |
| 로컬 모델 | 기존 `BoardItem`·`BoardDetail` UI 모델을 최대한 재사용한다. 로컬 보드에는 Import용 `client_board_uuid`와 생성·수정 시각을 별도로 보존한다. |
| 로컬 ID | 기존 UI의 `int` ID 계약을 유지할 수 있도록 서버 ID와 겹치지 않는 로컬 ID 규칙을 사용한다. Import 식별자는 로컬 ID가 아닌 `client_board_uuid`로 고정한다. |
| 보드 개수 | 앱 저장공간 한도 안에서 별도 개수 제한을 두지 않는다. |
| 데이터 수명 | 앱 재실행에는 유지되지만 앱 삭제·데이터 초기화 시 사라진다. 게스트 화면에 이 제한을 안내한다. |
| 첫 체험 | 최초 게스트 진입 시 로컬 튜토리얼 보드 1개를 한 번만 생성한다. 로그인 사용자의 기존 튜토리얼 플래그와 분리한다. |
| 진입 | 신규 사용자는 게스트/이메일 로그인을 선택한다. 로그인 이력이 있거나 세션이 복구되면 기존처럼 로그인 경로를 우선한다. |
| 로그아웃 | 로그인 사용자가 로그아웃하면 게스트로 자동 전환하지 않고 로그인 화면을 표시한다. |
| 협업 기능 | 참가·초대·담당자·멘션·Presence는 로그인 필요 안내 후 이메일 로그인으로 연결한다. |
| Import | `POST /v1/boards/import`; 사용자와 `client_board_uuid` 조합으로 idempotent하게 처리한다. |
| Import 실패 | 서버 트랜잭션을 롤백하고 로컬 원본을 유지한다. |
| Import 성공 | 서버 응답과 목록 조회로 반영을 확인한 보드만 로컬에서 삭제한다. |

## 2. M2 — 실제 로컬 보드 체험

### Outcome 2-1: 로컬 데이터 저장소

- Work: `lib/util/app_storage.dart`에 게스트 저장 키와 스키마 버전을 추가하고, `lib/service/guest_board_repository.dart`에서 보드·컬럼·카드 CRUD 및 순서 변경을 담당한다. 쓰기마다 전체 보드 문서를 일관된 상태로 저장한다.
- Work: 손상된 JSON은 원본을 백업 키에 보존하고 새 쓰기를 막은 뒤 복구 안내를 표시한다. 빈 목록으로 덮어써서 사용자 데이터를 잃지 않는다.
- Work: 제목, 설명, 우선순위, 상태, 마감일, 컬럼 완료 여부, 위치값과 `client_board_uuid`를 보존한다. 담당자와 멘션은 로컬 데이터에 만들지 않는다.
- Verify: `flutter test test/guest_board_repository_test.dart`

### Outcome 2-2: 기존 보드 UI에 게스트 데이터 연결

- Work: `lib/main.dart`에서 게스트를 `MainScaffold`로 보내고 `GuestHomeScreen` 플레이스홀더는 진입 경로에서 제거한다.
- Work: `boardListNotifierProvider`와 `boardDetailProvider`가 게스트일 때 로컬 저장소를 읽도록 분기한다. 보드·컬럼·카드의 생성, 제목/내용 수정, 완료, 이동, 삭제도 같은 로컬 저장소로 보낸다.
- Work: 게스트 상세에서는 `_BoardWsBridge`를 만들지 않고 REST 폴백도 실행하지 않는다. 서버용 낙관적 업데이트와 로컬 저장 결과가 충돌하지 않게 로컬 저장 후 Provider를 갱신한다.
- Work: 최초 게스트 진입 시 샘플 보드 1개를 생성해 곧바로 편집 가능한 화면을 보여준다.
- Verify: `flutter test test/guest_mode_flow_test.dart && flutter analyze`

### Outcome 2-3: 게스트용 메인 셸 정리

- Work: `AppDrawer`에서 로그아웃·회원 탈퇴·서버 더미 데이터 메뉴를 숨기고 `이메일로 로그인` CTA를 표시한다.
- Work: 게스트 보드는 모두 내 로컬 보드이므로 멤버 보드 필터를 숨긴다. 앱 평점, 언어, 테마, 화면 꺼짐 방지 같은 로컬 설정은 그대로 제공한다.
- Verify: 게스트 상태에서 Drawer와 보드 목록을 조작하며 네트워크 요청 및 세션 만료 메시지가 없는지 확인한다.

**M2 완료 기준:** 로그인 없이 샘플 보드와 새 보드를 생성하고, 컬럼·카드를 편집한 뒤 앱을 완전히 종료·재실행해도 동일한 내용이 보여야 한다.

## 7. 검증·배포 기준

- 현재 앱 API 주소는 NAS 실서버를 사용하지만, M2~M3의 게스트 동작은 네트워크를 전혀 사용하지 않는다.
- M4 Import API는 로컬 FastAPI에서 자동 테스트 후 NAS에 배포하고, 배포 전까지 앱에서 Import 진입을 노출하지 않는다.
- 웹 빌드는 검증 대상에서 제외한다.
- 실기기 독립 실행 검증은 Debug가 아니라 Profile 빌드를 사용한다.
